**这个 Skill 的核心洞察：积分不是"免费的"，它有市场汇率。** 麦麦商城里每一件"X 积分兑换 ¥Y 券"的商品，都在给积分标价。用这个汇率反推抽奖的期望值（EV），该不该抽，一算便知。

## 🧮 它怎么算

麦当劳不公示抽奖概率，但公示了完整的奖池结构。精算师的核心方法是**四层价值分层**——同样是中奖，价值性质完全不同：

```
第 1 步  query-my-account     → 积分资产（含⚠️本月将过期积分，最高优先级）
第 2 步  query-lottery-info   → 抽奖结构与 27 档奖池
第 3 步  四层价值分层：
   ┌─ 第①层 无条件回血：积分奖（中了直接回本，不依赖任何消费）
   ├─ 第②层 有条件变现：立减/抵扣券（面值 ¥1~8，必须下单消费才值钱）
   ├─ 第③层 增值型：折扣券（价值=原价×(1-折扣)，随客单价波动）
   └─ 第④层 大奖/权益：霸王餐、麦金卡、早餐卡
第 4 步  区间判断：最差情形回收率 + 奖池结构（有无"谢谢参与"档）
第 5 步  query-my-prizes      → 历史中奖记录，交叉验证真实手气
```

**决策标准（说人话版）：**

| 你的情况 | 结论 |
|---|---|
| 积分当现金攒着，近期不消费 | ❌ 抽奖≈负期望（积分奖均值回血仅 ~60%） |
| 本来就要吃麦当劳 | ✅ 券类奖品能激活，期望改善，可小抽怡情 |
| 积分本月过期 | ⚠️ 无论如何抽掉——归零永远比亏 67% 差 |

## 🔍 精算师勘察发现（2026-10-10 真实账号实测）

开发过程中用 MCP 真实接口勘察出的三个官方文档没写的事实，它们直接决定了算法设计：

1. **接口奖池里没有"谢谢参与"档——但实盘会空。** 27 档接口奖品全是实际奖品，最低档是"8 会员积分"（24 分抽一次），看似"必中"。但 2026-10-11 我们用 `draw-lottery` 实盘抽了 2 次：第 1 抽中 30 积分，**第 2 抽 win=false、奖品为空、24 分照扣**。结论：空奖真实存在，只是不落接口数据（或奖池配置动态调整）。「100% 中奖」的宣传在实盘视角下存疑。两抽总账：投入 48 分、回血 30 分，**回血率 62.5%，与本工具预测的积分奖均值回血 ~60% 几乎精准命中**。
2. **官方不公示中奖概率，点估计 EV 不可能。** 本工具因此不编造概率，改用**区间判断**：最差情形回收率（-67%）+ 奖池结构分析 + 分层价值评估，在信息不完全下给出可辩护的决策。
3. **商城列表存在"僵尸商品"。** `mall-points-products` 返回的部分到店兑换券查询详情时显示已下架——用列表页数据直接算汇率会拿到失真锚点，必须逐个验证商品状态。

```bash

python skill/actuary.py
```
